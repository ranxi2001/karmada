下一页每个生命周期状态分别由谁处理？

02 / 状态边界只自动处理一个交叉状态06 / 16

Proposed state policy / 目标策略

策略只接受 Assigned × NotStarted；实现还要挡住状态竞态

1 / 5只有一类状态允许自动重放
QUEUED没有有效 Placement，任务本来就在等待调度。scheduler 负责；Descheduler 不处理
ASSIGNED × NOTSTARTED对象已下发，但任务未开始；放置不可行并持续超过阈值。唯一自动路径：撤销 Placement 后重排
RUNNING / PARTIAL已经有执行进度，整任务重放可能造成重复计算或副作用。准入拒绝；并用执行围栏阻断竞态
SUCCEEDED / FAILED成功或失败都属于 Terminal；失败原因未必是集群放置。交任务控制器、TTL（生存时间清理）或显式失败策略
UNKNOWN状态缺失、过期、解释失败或证据相互冲突。fail closed（保守拒绝）并告警

本页回答目标契约拒绝 Running；事后再 suspend 仍会竞态，强保证必须从创建时就持有围栏。

03 / 状态来源让工作负载作者定义开始与终止07 / 16

Normalized lifecycle

Descheduler 消费统一 SchedulingState（调度状态），不猜 CR 字段

B 核心ResourceInterpreter（资源解释器）承载领域语义

建议接口 两个最小 hook（扩展接口）

GetTaskLifecycle(object, status)
→ NotStarted | Running | Succeeded | Failed | Unknown

IsRelocatable(object, status)
→ allowed, reason, evidence

接口名是设计建议，不是当前 API。工作负载作者映射原生字段；同一生命周期结果必须同时服务准入判断与迁移完成判断。

当前缺口 GracefulEvictionTask 只读取 Health / timeout，尚未接入这套 SchedulingState。

每个事实只认一个权威来源

是否 Assignedbinding.Spec.Clusters 与已生效 Placement。
是否 AppliedAggregatedStatusItem.Applied，只证明下发。
是否 StartedResourceInterpreter 的任务生命周期 hook。

03 / 决策门缺一个条件都不自动迁移08 / 16

Proposed gates / 目标准入门

先证明“可撤销”，再写 Binding

6 / 6全部为真才进入执行链
GATE 01 / OPT-IN

显式启用

策略声明允许自动重放；默认不扩大现有行为。

GATE 02 / ATOMIC

单目标 Placement

完整任务只占一个集群，不接受 Duplicated（复制）/ Divided（分片）模式。

GATE 03 / REVISION

Assigned、Applied 且版本一致

捕获 Binding 与任务 observed revision，拒绝陈旧观察。

GATE 04 / FENCE

NotStarted 且创建时围栏仍有效

准入握手或等价 Operator lock 持续冻结；事后 suspend 不算强围栏。

GATE 05 / INFEASIBLE

长期不可调度

Pending / Unschedulable 原因持续超过阈值，不把短暂抖动当失败。

GATE 06 / MEMORY

无在途任务与冷却

同一 source 未处于 eviction、exclusion 或 cooldown，避免重复触发。

ALL TRUE才调用 GracefulEvictCluster(source)；缺围栏时只能显式进入 best-effort 模式，不能给绝对安全承诺。

本页回答状态正确性优先于迁移覆盖率。

Proposed execution chain / 目标闭环

撤销源租约，排除原集群，按任务生命周期清理旧 Work

5 步detect · revoke · exclude · place · retire
01 / DETECT

发现未启动失败

Assigned、Applied、NotStarted、Infeasible 持续超阈值。

→
02 / REVOKE

写驱逐任务

GracefulEvictCluster(source) 从 Clusters 移除源并追加 task。

→
03 / EXCLUDE

源集群不可再选

ClusterEviction 读取 task，在 Filter（过滤）阶段拒绝 source。

→
04 / PLACE

scheduler 选新目标

沿现有过滤、打分和资源估算产生新单集群 Placement。

→
05 / RETIRE

RETENTION ≠ COMPLETION

PurgeMode=Gracefully 只延后删旧 Work；普通 task 仍仅按 Health / timeout 收尾。

SIMPLE SCHEDULER

Descheduler 写纠偏意图；现有 ClusterEviction 排源，scheduler 仍只做过滤、打分与选址。

FENCE REQUIRED

需从创建起冻结到 Placement commit；事后 suspend 与 revision 复核仍可能竞态。

本页回答已有原语能排源重排；围栏与 lifecycle-aware completion（生命周期完成判断）仍需新增。

Intent vs correction

千问要“排除失败来源后重放”，不是“重新算一次”

触发≠完成时间戳不能证明迁移完成

WorkloadRebalancer

面向用户显式发起的一批 workload 重新计算，适合主动均衡或策略变化后的 Fresh 调度。

写入只更新 spec.rescheduleTriggeredAt。
scheduler切换为 Fresh（全量重算），不参考旧结果重新计算。
source没有 GracefulEvictionTask，无法保证过滤原集群。

源码：workloadrebalancer_controller.go:189-239
≠

Descheduler + GracefulEviction

面向运行事实持续检测，可表达“撤销具体 source”；目标设计再补执行围栏与生命周期完成判断。

下一页上线前必须锁死哪些真实边界？

05 / 安全边界自动化只在约束内成立12 / 16

Proposed safety contract / 目标边界

原子放置、执行围栏、完成语义和持久记忆缺一不可

6 条任何一条不满足都拒绝自动动作
01 / ATOMIC + ALTERNATIVE

单目标且先证明有候选

策略必须是单集群 Placement；预演至少确认一个替代集群。Duplicated / Divided 与无候选任务都拒绝。

02 / PURGE MODE

Gracefully 不是执行围栏

它只决定何时删除源 Work，不能阻止任务在“检查 NotStarted”之后突然开始运行。

03 / COMPLETION

Health / timeout 不等于任务完成

A/B 必须把统一生命周期接入 evictiontask.go；普通 task timeout 只能记失败，不能冒充成功。

04 / PERSISTED MEMORY

不要借 scheduler queue 记历史

PriorityBasedScheduling 默认关闭并走 legacy rate-limiting queue；Attempts 只是内存调度尝试。source / attempt / cooldown / outcome 需另行持久化。

05 / TOCTOU RACE

围栏必须从任务创建时持有

准入握手冻结到 Placement commit，或 Operator 提供等价 lock；事后 spec.suspend 仍竞态，无协作只能 best-effort。

06 / OWNERSHIP

Binding 只允许一个纠偏写入方

Descheduler 持有自动纠偏；任务控制器持有 Running / Terminal；依赖资源需明确 PropagateDeps。

本页回答安全性来自明确拒绝条件，不来自更激进的重试。
